# Roadmap

Sequence outcomes by dependency and risk. Replace the starter stages below with project-specific outcomes from docs/project-brief.md. A roadmap item describes a demonstrable result, not a list of files to edit.

## P0 — Establish Context

- [ ] Complete the project brief and identify the primary user outcome.
- [ ] Record the verified current architecture and development commands.
- [ ] Identify the riskiest unknown and the evidence needed to resolve it.

## P1 — Prove the Core Path

- [ ] Deliver the smallest end-to-end path for the primary outcome.
- [ ] Validate important external boundaries with real evidence where safe.
- [ ] Capture material decisions as accepted ADRs before implementation.

## P2 — Make Behavior Reliable

- [ ] Cover expected behavior and important failure modes.
- [ ] Add the project-relevant quality, security, and operational checks.
- [ ] Make setup and verification reproducible from a clean checkout.

## P3 — Prepare Delivery

- [ ] Execute the complete verification checklist.
- [ ] Document known limitations and deferred work.
- [ ] Confirm the change history and handoff are reviewable.

## Deferred

Record explicitly deferred ideas here with the evidence or condition that would promote each one into the roadmap.
